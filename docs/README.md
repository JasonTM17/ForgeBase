# ForgeBase Documentation

Languages: English | [Tiếng Việt](README.vi.md)

This directory is the public documentation hub for ForgeBase. Template source
code and template READMEs own the runnable details; the documents here own
navigation, decisions, the evidence vocabulary, and the maintainer workflow

## Evidence Model

ForgeBase uses four public evidence labels:

| Label | Meaning |
| --- | --- |
| `PASS` | The stated check ran and passed for the named scope. |
| `FAIL` | The stated check ran and found a defect. |
| `NOT_RUN` | The check did not run; no pass is implied. |
| `BLOCKED` | The check could not complete because a required tool, service, credential, permission, or decision was unavailable. |

Keep release evidence exact. A local command, a pushed branch, a GitHub
Actions run, a tag, and a published artifact are separate proof points.

## Documentation Standards

- English is the canonical documentation language; `.vi.md` files are faithful
  translations kept aligned in meaning, not literal word-for-word copies.
- Section heading `## 5. README requirements (per template)` in the
  [template specification](template-specification.md) is referenced by anchor
  from [conventions](conventions.md) — do not renumber or reword it without
  fixing the link.
- The [verification matrix](verification-matrix.md) is generated; edit
  template metadata or the generator, never the matrix rows by hand.
- Commands in docs must be copy-pasteable and portable — no personal paths,
  no hostnames.

## Keeping Docs Healthy

For documentation-only changes, run the cheapest checks that prove the edit:

```bash
python scripts/update_verification_matrix.py --check
python scripts/validate_templates.py --quiet
git diff --check
```

When links or navigation change, also run a Markdown relative-link check
before opening or merging a PR.
