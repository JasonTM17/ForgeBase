## Evidence Model

ForgeBase uses four public evidence labels:

- `PASS`: the stated check ran and passed for the named scope.
- `FAIL`: the stated check ran and found a defect.
- `NOT_RUN`: the check did not run; no pass is implied.
- `BLOCKED`: the check could not complete because a required tool, service,
  credential, permission, or decision was unavailable.

Keep release evidence exact. A local command, a pushed branch, a GitHub Actions
run, a tag, and a published artifact are separate proof points.

## Public And Private Boundary

Public docs may describe the AgentKit workflow and verification vocabulary.
They must not publish local runtime files, private skill registries, prompts,
or execution ledgers. The public docs authority lives under this directory and
the root community files. Private local AgentKit paths stay ignored.

## Keeping Docs Healthy

For documentation-only changes, run the cheapest checks that prove the edit:

```bash
python scripts/update_verification_matrix.py --check
python scripts/validate_templates.py --quiet
git diff --check
```

When links or navigation change, also run a Markdown relative-link check before
opening or merging a PR.
